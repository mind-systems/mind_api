# Биометрические данные — агрегация на сервере

`GET /sessions/runs/:id/biometrics` возвращает сырые сэмплы из `bio_session_samples`. При добавлении параметра `bucketSec` сервер агрегирует данные на лету — в Postgres — и возвращает компактный downsampled набор вместо сырого потока.

## Параметры запроса

| Параметр | Тип | Описание |
|----------|-----|----------|
| `from` | ISO 8601 | Начало окна, включительно. |
| `to` | ISO 8601 | Конец окна, исключительно `[from, to)`. |
| `bucketSec` | число | Ширина бакета в секундах. Включает агрегацию. Без него — сырые сэмплы. |
| `agg` | `minmax` \| `avg` \| `lttb` | Режим агрегации. По умолчанию `minmax`. |

## Сырой режим (без `bucketSec`)

Возвращает плоский массив `{ timestamp, sampleType, data }` из всех батчей за указанное окно, отсортированный по `timestamp`. Если результат превышает 50 000 сэмплов или 60 000 строк из БД — `413 Payload Too Large`.

## Агрегированный режим (`bucketSec` задан)

Сервер делает один SQL-запрос: `jsonb_array_elements` разворачивает батчи, `jsonb_each` раскрывает поля `data`, `jsonb_typeof='number'` фильтрует только числовые листья — без привязки к именам полей. Схема `data` сервером не интерпретируется.

Результат: массив синтетических `{ timestamp, sampleType, data }` — по одному или два сэмпла на бакет в зависимости от режима.

### Режимы

**`minmax`** — spike-preserving envelope. На каждый `(sampleType, bucket)` — два сэмпла: min в `bucketStart`, max в `bucketStart + bucketSec/2`. Пустые бакеты пропускаются. Хорошо передаёт выбросы, но рисует пилообразную кривую.

**`avg`** — один сэмпл на `(sampleType, bucket)` в `bucketStart + bucketSec/2`, значения — среднее по полям. Кривая гладкая, выбросы сглаживаются.

**`lttb`** — один сэмпл на `(sampleType, bucket)`, выбранный per-field по критерию максимальной площади треугольника относительно первой и последней точки бакета. Сохраняет форму кривой лучше `avg`, без запаздывания скользящего среднего. Реализован bucket-local вариант (не классический LTTB): треугольник строится к первой/последней точке текущего бакета, а не к ранее выбранной точке и центроиду следующего бакета — это гарантирует независимость бакетов и позволяет тайлинг. Ограничение: пик на краю бакета может не попасть в результат (площадь 0 → fallback к max отклонению от среднего).

### Тайлинг

Бакеты привязаны к абсолютному началу эпохи (epoch 0), а не к `from` запроса. N смежных запросов с одинаковым `bucketSec` и выровненными по `bucketSec` границами `from`/`to` возвращают идентичный результат одному запросу на всю сессию. Клиент обязан выравнивать границы окон: `from = floor(from / bucketSec) * bucketSec`.

### Фильтрация мусорных timestamp

Сэмплы с `timestamp ≤ session.startedAt − 60 000 мс` отбрасываются — защита от epoch-0 и аналогичного мусора, который мог попасть в jsonb на старых клиентах.

### Лимиты

| Путь | Лимит |
|------|-------|
| Сырой (`points` режим) | 50 000 сэмплов / 60 000 строк БД |
| `lttb` (grouped SQL) | 3 000 000 строк points-запроса |
| `minmax`, `avg` (grouped SQL) | лимит отсутствует — Postgres возвращает только агрегаты |

При превышении — `413 Payload Too Large`.
