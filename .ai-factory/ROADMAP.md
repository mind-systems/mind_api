## Phase 16 — Feature: BciDevice resource

Lightweight per-user resource for tracking paired Neiry headbands by hardware serial. Originates from a mobile-team request — see `.ai-factory/notes/01-bci-device-resource.md` for the full context. Scope: gRPC only (no REST). BCI is intentionally **not** wired into the realtime stream pipeline and is **not** propagated through the `sync` changes journal (`src/sync/`, `src/changelog/`) — paired-device lists are not synced across a user's phones; each phone calls `Register` on first pairing locally.

- [x] **Author `proto/bci_devices.proto` and regenerate stubs** — Create `proto/bci_devices.proto` modelled on the structure of `proto/sync.proto` (package `mind`, comments mapping each message to its DTO/entity, identity comes from the auth interceptor and is **not** included in request messages). Define one entity message `BciDevice { string id = 1; string serial = 2; string created_at = 3; string updated_at = 4; }` (timestamps as ISO-8601 strings to match the project convention used in `SyncEventDto`). Define service `BciDevicesService` with three RPCs: `List(google.protobuf.Empty) returns (ListBciDevicesResponse)` where `ListBciDevicesResponse { repeated BciDevice devices = 1; }`; `Register(RegisterBciDeviceRequest) returns (BciDevice)` where `RegisterBciDeviceRequest { string serial = 1; }`; `Delete(DeleteBciDeviceRequest) returns (google.protobuf.Empty)` where `DeleteBciDeviceRequest { string id = 1; }`. Import `google/protobuf/empty.proto`. Regenerate TypeScript stubs into `proto/generated/` via `npm run proto:gen` (see `proto/README.md`). Do not edit files under `proto/generated/` by hand — they are produced by `ts-proto`. [5m 22s]

- [x] **Migration `AddBciDevicesTable`** — Generate the file via `npx typeorm migration:create src/migrations/AddBciDevicesTable` (never hand-craft the timestamp prefix — see existing files like `src/migrations/1774863293946-InitialSchema.ts` for naming format). Create table `bci_devices` with columns: `id uuid PRIMARY KEY DEFAULT uuid_generate_v4()`, `user_id uuid NOT NULL` with foreign key `REFERENCES users(id) ON DELETE CASCADE`, `serial varchar NOT NULL`, `created_at timestamptz NOT NULL DEFAULT now()`, `updated_at timestamptz NOT NULL DEFAULT now()`. Add unique constraint `UQ_bci_devices_user_serial` on `(user_id, serial)`. Add index `IDX_bci_devices_user_id` on `(user_id)` to back the `List` query. Implement both `up` and `down`. Migrations run automatically on startup (`migrationsRun: true` in `database.config.ts`). [6m 57s]

- [x] **`BciDevice` entity + `BciModule` skeleton** — Create `src/bci/entities/bci-device.entity.ts` with `@Entity('bci_devices')`, typed columns matching the migration (use `@PrimaryGeneratedColumn('uuid')`, `@Column({ name: 'user_id' }) userId: string`, `@Column() serial: string`, `@CreateDateColumn({ name: 'created_at', type: 'timestamptz' })`, `@UpdateDateColumn({ name: 'updated_at', type: 'timestamptz' })`). Add `@Index(['userId', 'serial'], { unique: true })`. Create `src/bci/dto/register-bci-device.dto.ts` with a single `serial: string` field (class-validator: `@IsString() @IsNotEmpty()`). Create `src/bci/bci.module.ts` that calls `TypeOrmModule.forFeature([BciDevice])`, declares the controller, registers the service as a provider, and exports nothing (no other module needs `BciDeviceService`). Register `BciModule` in `AppModule` next to `BreathSessionsModule`. `@InjectRepository(BciDevice)` must only be used inside `BciModule` (per the modular monolith rule in `CLAUDE.md`). [9m 50s]

- [ ] **`BciDeviceService`** — Create `src/bci/bci-device.service.ts` with three methods. `listForUser(userId: string): Promise<BciDevice[]>` — returns rows for the user ordered by `updated_at DESC` so the most recently used device is first. `register(userId: string, serial: string): Promise<BciDevice>` — idempotent: if a row with the same `(userId, serial)` exists, **force-bump `updated_at` to the current time** and return the reloaded row; otherwise insert a new row. Important: `@UpdateDateColumn` is only refreshed by TypeORM when `.save()` detects a real change to the entity — calling `repo.save(existingRow)` unchanged will **not** move the timestamp, which breaks the `List` ordering for the exact case it exists for (re-registering the most-recently-used device). Use one of these two patterns explicitly: (a) `await repo.update({ userId, serial }, { updatedAt: () => 'CURRENT_TIMESTAMP' })` followed by `repo.findOneByOrFail({ userId, serial })`, or (b) load the row, set `row.updatedAt = new Date()` manually, then `repo.save(row)`. Implementation must be safe against the unique-constraint race (catch the unique-violation `QueryFailedError` and re-fetch — Postgres error code `23505`). `delete(userId: string, id: string): Promise<void>` — fetch by `id`; if not found throw `RpcException({ code: GrpcStatus.NOT_FOUND, message: 'BCI device not found' })`; if `row.userId !== userId` throw `RpcException({ code: GrpcStatus.PERMISSION_DENIED, message: 'BCI device belongs to another user' })`; otherwise delete. Ownership checks live here, not in the controller. Imports: `RpcException` from `@nestjs/microservices`, `status as GrpcStatus` from `@grpc/grpc-js` — same imports used in `src/realtime/sync-stream.grpc.controller.ts`.

- [ ] **`BciDevicesGrpcController`** — Create `src/bci/bci-devices.grpc.controller.ts` modelled on `src/realtime/sync-stream.grpc.controller.ts`. Apply `@Controller()`, `@UseFilters(GrpcExceptionFilter)` and `@UseInterceptors(GrpcAuthInterceptor)` (from `src/grpc/`). Each RPC takes `@GrpcCurrentUser() user: JwtPayload | null` (decorator at `src/grpc/decorators/grpc-current-user.decorator.ts`, `JwtPayload` from `src/users/interfaces/auth.interface`); if `user` is null throw `RpcException({ code: GrpcStatus.UNAUTHENTICATED, message: 'Missing user context' })`. Three methods decorated with `@GrpcMethod('BciDevicesService', 'list' | 'register' | 'delete')`, each delegating to the service and mapping the `BciDevice` entity to the generated proto message (convert `Date` fields to ISO strings via `.toISOString()`). `List` returns `{ devices: [...] }`; `Delete` returns `{}` (Empty). No streaming RPCs — all unary.
