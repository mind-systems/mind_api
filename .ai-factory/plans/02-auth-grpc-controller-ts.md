### Phase 2: gRPC exception filter

- [x] **Task 2: Create `src/grpc/grpc-exception.filter.ts`** (depends on Task 1)
  Files: `src/grpc/grpc-exception.filter.ts`
  Create a global gRPC exception filter that catches `HttpException` and converts it to `RpcException` with the correct gRPC status code. NestJS's built-in `BaseRpcExceptionFilter` only handles `RpcException` — any `HttpException` thrown by existing services (e.g., `UnauthorizedException`, `NotFoundException`, `HttpException(429)`) surfaces as an opaque `INTERNAL` (code 13) error without this filter.

  Use `@Catch(HttpException)` and implement `ExceptionFilter`. Map HTTP status codes to gRPC `Status` enum from `@grpc/grpc-js`:

  | HTTP status | gRPC status | Constant |
  |---|---|---|
  | 400 Bad Request | 3 | `Status.INVALID_ARGUMENT` |
  | 401 Unauthorized | 16 | `Status.UNAUTHENTICATED` |
  | 403 Forbidden | 7 | `Status.PERMISSION_DENIED` |
  | 404 Not Found | 5 | `Status.NOT_FOUND` |
  | 409 Conflict | 6 | `Status.ALREADY_EXISTS` |
  | 429 Too Many Requests | 8 | `Status.RESOURCE_EXHAUSTED` |
  | default | 13 | `Status.INTERNAL` |

  The filter should:
  1. Extract the HTTP status via `exception.getStatus()`
  2. Extract the message via `exception.getResponse()` (handle both string and object shapes)
  3. Map to gRPC status using the table above
  4. Throw `new RpcException({ code: grpcStatus, message })` via `throwError(() => ...)` from rxjs

  Follow the existing pattern in `src/realtime/filters/ws-exception.filter.ts` for extracting messages from `HttpException.getResponse()`.

### Phase 3: Controller implementation

- [x] **Task 3: Create `src/users/auth.grpc.controller.ts`** (depends on Tasks 1, 2)
  Files: `src/users/auth.grpc.controller.ts`
  Create the gRPC controller that implements the `AuthServiceController` interface from `proto/generated/auth`. Apply `@Controller()` and `@AuthServiceControllerMethods()` class decorators (the latter auto-registers `@GrpcMethod` for every RPC). Apply the gRPC exception filter via `@UseFilters(GrpcExceptionFilter)` at the class level so all methods are covered.

  Inject four services: `AuthCodeService`, `AuthService`, `PersonalAccessTokenService`, `SessionService`.

  **Public methods (no auth):**

  - `sendCode(request)` — call `authCodeService.sendCode(request.email, request.locale)`, return `{ message: 'If this email is registered, a code has been sent.' }`. Mirrors `AuthController.sendCode`.
  - `verifyCode(request)` — call `authCodeService.verifyCode(request.email, request.code, request.language)`, map the returned `AuthResponseDto` to proto `AuthResponse`. The proto returns both token and user in the message body (unlike HTTP which puts the token in a response header).
  - `googleAuth(request)` — call `authService.signInWithGoogle(request.serverAuthCode, request.language, request.redirectUri)`, same DTO-to-proto mapping as `verifyCode`.

  **Protected methods (require auth via 1.4 interceptor):**

  Apply `@UseInterceptors(GrpcAuthInterceptor)` on each protected method. Use `@GrpcCurrentUser()` parameter decorator to receive the `JwtPayload`.

  - `logout(request, metadata: Metadata)` — extract raw bearer token from gRPC metadata: call `metadata.get('authorization')[0]?.toString()` (`.toString()` is required because `Metadata.get()` returns `(string | Buffer)[]` — a `Buffer` value would break `.startsWith()` / `.slice()` without conversion). Strip `Bearer ` prefix, call `sessionService.revoke(token)`. Cannot delegate to `authService.logout()` because it expects an Express `RequestWithUser` object. Return `{ message: 'Logout successful.' }`.
  - `createToken(request)` — call `personalAccessTokenService.create(user.sub, request.name)`, map result: convert `createdAt: Date` to ISO-8601 string.
  - `listTokens(request)` — call `personalAccessTokenService.list(user.sub)`, map each `PersonalAccessToken` entity to proto `TokenDto` (`createdAt` and `lastUsedAt` to ISO-8601 strings or `undefined`). Return wrapped in `{ tokens: [...] }`.
  - `deleteToken(request)` — call `personalAccessTokenService.revoke(request.id, user.sub)`, return `{ message: 'Token revoked.' }`.

  **DTO-to-proto mapping details:**

  - `UserRole` enum: service uses string values (`'user'`, `'admin'` from `src/users/interfaces/user-role.enum.ts`), proto uses numeric values (`0 = USER`, `1 = ADMIN`). Create a local `toProtoUserRole(role: string): number` helper in the controller file that maps between them.
  - `AuthResponseDto` to `AuthResponse`: map `user` fields + `accessToken` directly; apply `toProtoUserRole` to `user.role`.
  - Date fields in token responses: call `.toISOString()` on `Date` values to produce ISO-8601 strings.
