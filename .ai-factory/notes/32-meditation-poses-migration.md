# Meditation Poses — Migration

**Date:** 2026-06-03
**Source:** conversation context

## Key Findings

- Table is static reference data — no `user_id`, no `updated_at`, no soft delete.
- Six rows seeded inline in the same `up()` that creates the table. No separate seeder.
- UUIDs generated by `uuid_generate_v4()` at insert time — not pre-agreed with mobile.
- `down()` drops the table (seed rows go with it).

## Details

### Generate the file

```bash
npx typeorm migration:create src/migrations/AddMeditationPosesTable
```

Never hand-craft the timestamp prefix.

### `up()` body

```sql
CREATE TABLE meditation_poses (
  id            uuid        PRIMARY KEY DEFAULT uuid_generate_v4(),
  slug          varchar     NOT NULL,
  display_order smallint    NOT NULL,
  CONSTRAINT UQ_meditation_poses_slug UNIQUE (slug)
);

INSERT INTO meditation_poses (slug, display_order) VALUES
  ('easy',       1),
  ('lotus',      2),
  ('half_lotus', 3),
  ('seiza',      4),
  ('chair',      5),
  ('savasana',   6);
```

Use `uuid_generate_v4()` (not `gen_random_uuid()`) — project convention from existing migrations (`AddBciDevicesTable`, `AddNfbCalibrationRecordsTable`).

### `down()` body

```sql
DROP TABLE meditation_poses;
```

### Design rationale

Poses are curated content. Migration-only additions are intentional — strict change control, no admin endpoint needed.
