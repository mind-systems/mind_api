# ARCHITECTURE.md drift — surfaced by a cross-repo CLAUDE.md alignment pass

**Date:** 2026-07-19
**Source:** cold-agent rehydration into `mind_api` during the `~/projects/mind` CLAUDE.md-tree alignment task (`skills` roadmap 2.1). `ARCHITECTURE.md` was read-only ground truth for that task and was not edited — it belongs to the `mind_api` team. Recorded here for them to resolve.

## Key Findings

1. **Stack drift: `ARCHITECTURE.md` still frames the API as REST; the code is gRPC-first.** Line 9 states "Project type: REST API backend for a mobile mindfulness app," and the `## Layer / Module Communication` diagram (lines 60-69) and its "Controller: HTTP concerns only" code comment (line 132) both describe a plain `HTTP Request → Controller → Service → Repository` flow — yet `## Key Principles` item 2 (line 92), in the same file, already says "gRPC controllers handle request/response mapping." The doc contradicts itself, and the code sides with the gRPC framing: `src/main.ts` bootstraps the app as a `Transport.GRPC` microservice (`NestFactory.create` + `createMicroservice` on `0.0.0.0:50051`), and 14 of the app's 19 controllers are `*.grpc.controller.ts`. The 5 that remain HTTP (`health.controller.ts`, `sessions.controller.ts`, `users/controller/auth.rest.controller.ts`, `users/controller/google-callback.controller.ts`, `nfb-calibration/nfb-calibration.rest.controller.ts`) serve `mind_web`'s REST needs and the OAuth redirect callback — a real secondary surface, not a rounding error, but gRPC is the primary transport for the mobile client. → reframe the Overview/Decision Rationale and the Layer/Module Communication diagram as gRPC-first with REST as the documented secondary surface, and resolve the line-92 self-contradiction in the same pass.

2. **`## Features` has empty commit-hash cells** on: User profile, Device ping, Time-of-day suggestions, Session statistics (streak, duration, complexity), Sync change journal (TTL, purge), Sync unary (cursor, full-resync sentinel) — 6 rows total (`ARCHITECTURE.md:209,211,214,215,217,218`). `temporal-tree`'s history reconstruction has nothing to walk for these — no hash means no patch, no roadmap snapshot, no surrounding commits are reachable for that feature. → backfill the hashes (`git log --oneline -- <files>` per feature, same convention as the populated rows).

3. **Adjacent, not `ARCHITECTURE.md` itself: no proto/gRPC toolchain page in the CLAUDE.md documentation index**, despite gRPC being the primary transport. `docs/realtime/protocol.md` documents the realtime domain's own message contracts (ModuleStateService, ModuleInstructionService) but nothing documents the toolchain itself — the `proto:gen` script (`package.json:27`, `protoc` + `ts_proto` → `proto/generated`), where the generated stubs land, or the general shape of a proto-backed controller outside the realtime domain. Consumers (`mind_mcp`, `mind_mobile`) already depend on this pipeline per the Proto contract ownership convention. → worth a `docs/` page and a CLAUDE.md Documentation row.
